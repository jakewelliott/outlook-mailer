# Decisions and why

Agreed with Jake between 2026-10-25 and 2026-11-11. The README summarises these; this file has the reasoning.

| Topic | Decision | Why |
|---|---|---|
| Sending account | Free personal @outlook.com. Nothing paid. | Jake's requirement. |
| Sending method | Microsoft Graph `sendMail`, delegated OAuth. | Microsoft switched off password/app-password SMTP for Outlook.com in Sept 2024. OAuth is the only way left. |
| App registration | Lives in the Entra tenant that comes with a free Azure account. | Personal accounts can no longer register apps outside a directory. $0; the card is only for identity checks. The trial subscription is disabled after 30 days but the directory remains (post-trial behaviour not officially confirmed; see docs/entra-setup.md). Microsoft may delete directories it considers inactive, so sign in to the Entra admin center every couple of months. |
| Sign-in | One-time device code from the web UI (enter a code at the link the app shows, normally microsoft.com/link for personal accounts). Token stored in `/data`, encrypted if `TOKEN_CACHE_KEY` is set. | The Outlook password can't be used by apps. The token renews itself; re-sign-in only after a password change or ~90 days unused. |
| Message format | MIME: HTML with a plain-text alternative. | Graph's JSON send allows one body only; MIME keeps the text version and lets us add List-Unsubscribe headers. |
| Sent Items | Copies saved to Outlook's Sent folder. | A record of what went out. |
| Pacing | 6 per minute, 250 per day by default (env-configurable). | Microsoft doesn't publish free-account limits; ~300/day is reported. Staying under it avoids the account being flagged or locked. |
| Email type | Commercial. Footer has the advertisement notice (default on), postal address and unsubscribe link. | CAN-SPAM requirements for commercial email. |
| Unsubscribe | One-click link only (no reply-to-unsubscribe). Opt-outs appended to `/data/unsubscribed.txt` as `email<TAB>datetime`. | Jake removes them from his CSV himself. The link must keep working 30+ days after a send (CAN-SPAM). |
| Unsubscribe rate limit (stage 13) | Keyed on the `CF-Connecting-IP` header, falling back to the socket peer address when it is absent. Never on `request.client.host` or `X-Forwarded-For`. | Cloudflare sets `CF-Connecting-IP` and overwrites any client value. uvicorn's proxy-headers client address comes from the leftmost `X-Forwarded-For` entry, which the client controls. Only someone hitting the LAN port directly could spoof the header, which is acceptable. Logs may show spoofed IPs. |
| Send-time safety net | Every recipient is checked against `unsubscribed.txt` before sending. | If an opt-out is missed in the CSV it still isn't emailed. CAN-SPAM requires honouring opt-outs within 10 business days. |
| Subscription status | Optional dropdown. If set, the user picks which values to send to. If blank, everyone is eligible. | Square exports include "Email Subscription Status"; other exports may not. |
| Status defaults (stage 4) | Square's real "Email Subscription Status" values are `subscribed`, `unsubscribed`, blank and `bounced` (per Jake). Values start unticked if they look like an opt-out, matched on whole words: `unsub`/`notsub`/`nonsub`/`bounc`… prefixes, "opt(ed) out", negative words (`no`, `not`, `false`, `0`…), and `pending`, `unconfirmed`, `cleaned`, `unknown`. `opt` alone is not a signal, so `opted in` stays ticked. Blank is shown as "(blank — no status)", starts unticked, and can be ticked to send to rows that have an email but no status; rows with no email are always reported as missing email. Duplicates are checked before the status filter. | Bounced addresses can't receive mail and unconfirmed states aren't consent, so the safe default is not to send. Square's email field is optional, so a blank status usually comes with a blank email; when a row has an email but no status, Jake wants to decide. Checking duplicates first is conservative: if the first row for an address is skipped (e.g. `unsubscribed`), a later row with the same address is a duplicate and isn't sent either. The user can override every default. |
| Column mapping | Two required dropdowns (email, first name) from the CSV header. | Works with any export without caring about its format. |
| Body editor | Markdown: bold, italic, strike, `++underline++`, links, lists. | Simple formatting without a rich-text editor. Markdown has no underline, so `++text++` was chosen. |
| Template | Based on Cerberus (MIT), Christmas styled. | Proven to render in classic Outlook, Gmail, Apple Mail, dark mode. |
| Images | Hosted by the app at `/img/*`; all free-license, credited in `app/static/email-img/CREDITS.md`. | Hosted images look better than none; the server is already public for unsubscribe. Container must stay up 30+ days after sending. |
| Access | Cloudflare tunnel + Cloudflare Access app; `/u/*`, `/img/*`, `/healthz` bypassed. App verifies the Access JWT on admin pages. No separate app login. | Cloudflare decides who can use the app. The JWT check stops anyone reaching the admin pages via the LAN port. |
| Domain | `PUBLIC_BASE_URL` env var (Jake uses `https://the-calico-barn.jakewelliott.com`). | Easy to change. |
| Port | 8765. | Free on the server. |
| Repo / image | Public repo `jakewelliott/outlook-mailer`; public image `ghcr.io/jakewelliott/outlook-mailer`. | No secrets in either. A public image means Unraid can pull without logging in (`/root` is wiped on reboot). |
| CSV retention | Raw CSV deleted after the campaign; send log kept. | The CSV changes every time. |
| Stack | Python 3.12, FastAPI, Jinja2, SQLite. | Small, no frontend build, first-class Microsoft auth library (MSAL). |
| Referrer-Policy | `same-origin` on admin responses; `no-referrer` on public paths (`/u/*`, `/img/*`, `/healthz`). `Origin: null` is never accepted. | Under `no-referrer`, Chromium and Firefox send `Origin: null` and no Referer on same-origin form POSTs, so the Origin check would reject every admin form. Accepting `null` would also accept requests from sandboxed frames and other opaque origins. `same-origin` still sends nothing to other sites. |
| CSRF cookie | `om_csrf` is `SameSite=Lax`, HttpOnly, Secure. | The signed (HMAC) token is the real protection. `Strict` drops the cookie after cross-site navigations such as the Access login redirect, so the nonce is reissued and open forms' tokens stop working. |
| Merge field syntax (stage 5) | Field names are case-insensitive, spaces/tabs inside the braces are allowed, the fallback (`{{first_name\|Friend}}`) is trimmed and can't contain `{`, `}`, `\|` or a line break. Every `{{` must start a valid field: there is no literal `{{`, and anything else starting with `{{` (or a `{%` tag) is an error that blocks sending. Rendering is one pass. For Markdown, placeholders are swapped for letter-and-digit tokens before conversion and put back after, then merged per recipient. | Forgiving about case and spacing, strict about everything else, so typos such as `{{first_name}` are caught before sending instead of going out as-is. Markdown would otherwise escape `&` in fallbacks (then escaped again by the merge), percent-encode `{{` in link URLs and split `\|` in tables. |
| Markdown body (stage 6) | markdown-it-py (CommonMark) with only the listed syntax. A single line break is kept as a line break. `###` and deeper are shown as `##`. Strike is `<s>`, underline is `<u>` from a small `++` rule modelled on `~~`. Code blocks, inline code, quotes, rules, `---` underline headings, reference links and tables are off (shown as text); images are an error. Bare URLs are not auto-linked. Links must be `https`/`http`/`mailto`, else an error. Merge fields in a link only after a fixed `http(s)://host` and a `/`, `?` or `#`, or as exactly `mailto:{{email}}`; their values are percent-encoded (only `@` kept) then HTML-escaped. Only the placeholders found in the raw body are filled in after conversion. | Jake types in a textarea and expects Enter to start a new line. Features that are off would surprise him more than help (indenting text made code blocks; `Thanks\n---` made a heading). Auto-linking needs another dependency and mail apps link bare URLs anyway. A placeholder before or in the host would let a recipient's value choose the site or scheme. Filling only known placeholders means escapes like `{\{` can't create new merge fields. |
| Email template (stage 7) | Cerberus fluid layout (600px max) with the hybrid version's VML background block. Header: a public-domain Christmas-tree photo as a background behind live text (business name, "Merry Christmas", tagline), dark green `bgcolor` underneath. Cream card with a small holly divider, gold rules, deep-red CAN-SPAM footer. Dark mode via `prefers-color-scheme` (Apple Mail, iOS) and `[data-ogsc]`/`[data-ogsb]` (Outlook.com, Outlook apps) in separate `<style>` blocks; css-inline inlines the rest and keeps the blocks. Images get versioned names and are cached for a year as immutable. A blank "why you're receiving this" uses a default sentence naming the business. | Live text instead of text baked into an image reads with images off, scales on phones and can be changed per campaign. Gmail drops a whole `<style>` block when it meets a selector it doesn't like, so the Outlook-only rules are kept apart. Light text on a dark photo and a cream outline on the holly survive Gmail's dark-mode colour inversion. Sent emails link to image URLs for good, so a changed image must get a new name. |
| Compose and preview (stage 8) | The message is stored per draft (`draft_content`); footer and header fields are also saved app-wide (`settings`, key/value) and prefill new drafts. The preview is the last saved version, rendered by the same path as sending (`compose.render_message`), served from `/send/<id>/preview.html` and `preview.txt` with their own CSP (`default-src 'none'; style-src 'unsafe-inline'; img-src 'self' <PUBLIC_BASE_URL origin>`, `frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN`) in `<iframe sandbox>` without scripts. A route opts in with `security.use_email_preview_headers`; every other response keeps the strict CSP and `DENY`. Dark preview repeats the dark-mode rules outside the media query. Size is measured for the longest first name and address on the list, and for an empty first name (merge fallbacks): warn above 90 KB, refuse to save above 102 KB. Unsubscribe tokens are `base64url(lower-cased email) . base64url(HMAC-SHA256(key, email)[:16])`, the key derived from `UNSUBSCRIBE_SECRET` with a purpose string. | The email needs inline styles, which the admin CSP forbids, so it gets its own narrow policy rather than loosening the main one; a sandbox without `allow-scripts`/`allow-same-origin` keeps the rendered email inert. An iframe can't be forced into `prefers-color-scheme: dark`, so the preview approximates Apple Mail. Gmail clips HTML over about 102 KB and the clipped part holds the unsubscribe link. A 128-bit MAC keeps links short and unguessable; the purpose string keeps unsubscribe and CSRF tokens apart. |
| Messages and transports (stage 9) | `app/message.py` builds each email as `multipart/alternative` (text, then HTML; UTF-8; quoted-printable, or base64 when shorter), CRLF, 7-bit, with `From`, one `To`, `Subject`, `Date`, `Message-ID` at the `PUBLIC_BASE_URL` host, `List-Unsubscribe` and (for https) `List-Unsubscribe-Post`. Never `Cc`, `Bcc` or `Reply-To`; transports check the message is addressed only to its recipient. Any header value with a control character or line separator is refused. `From` is always written: the signed-in address once stage 12 supplies it, else `sender@example.invalid` (mock). Addresses go out as ASCII (IDN domains in punycode); a non-ASCII local part is refused. A transport returns a `SendResult` (ok / retryable with `Retry-After` / permanent / auth error) instead of raising. The mock writes `DATA_DIR/outbox/*.eml` (0700/0600) and can script failures per recipient and attempt. | RFC 5322 requires a From, and Graph sends from the signed-in mailbox anyway (another address may be refused as send-as). Quoted-printable keeps the `.eml` readable and every line under 78 characters; 7-bit survives every hop. Python folds a long `List-Unsubscribe` into encoded words mail apps don't read, so it is written raw on one line. Results keep retry and stop decisions in the send engine and let the mock produce every outcome. Non-ASCII local parts need SMTPUTF8, which isn't worth it for a rare case. |
| Send engine (stage 10) | One asyncio worker task in the app process, one recipient at a time. A campaign snapshots the saved content (JSON + SHA-256 hash) and the eligible recipients when it starts; only one campaign can be unfinished (queued, sending, paused, paused for the daily cap, or stopped by an error) at a time, and each upload is sent once. Pacing (`60 / SEND_RATE_PER_MINUTE` s between transport calls) and the rolling 24 h `DAILY_SEND_CAP` are computed from a `send_log` table across all campaigns; a send whose outcome is unknown counts against the cap, failed ones don't. Retries: 30 s, 2 min, 10 min, 3 attempts in all (`Retry-After`: see Throttling); permanent failures aren't retried; an auth error stops the campaign without counting against the recipient; 5 failed attempts in a row stop it. Pause, resume and cancel are database changes the worker sees at its next step; cancelling marks waiting recipients `not_sent`. `unsubscribed.txt` is re-read (when its size or mtime changes) before every message, matching IDN addresses in Unicode or punycode. Progress by polling a JSON endpoint every 3 s. | Simple and enough for a few hundred messages a day. Snapshots mean later edits can't change a running send. Logging transport calls, not recipients, makes the cap and pacing survive restarts and span campaigns. Counting "unknown" as sent stays on the safe side of Microsoft's limit. No websockets: polling needs nothing special from Cloudflare and works behind Access. |
| Interrupted sends (stage 10) | The recipient is set to `sending` and committed **before** the transport is called. If the app stops before the outcome is written, the next start marks that recipient `failed` with "interrupted during send — may or may not have been delivered; check Sent Items" and **never resends it automatically**. On a normal shutdown the worker first lets an in-flight send finish (up to 15 s) and starts no new one (a recipient already marked `sending` but not yet handed to the transport goes back to `pending`, uncounted). | Graph may have accepted the message before the crash, and there is no way to ask it. A missed email can be resent by hand after checking Sent Items; a double send can't be undone. At most one recipient per crash is affected. |
| Transport per send (stage 10) | Each campaign stores the `MAIL_TRANSPORT` it was created with. The worker only sends campaigns whose transport matches the current one; resuming a mismatched campaign is refused ("This send was started in mock mode; cancel it and start a new one"); pausing and cancelling are allowed. The transport is shown on the send's page and in the list. | A mock run skips the test-send gate. Without this, a mock campaign left paused or stopped would go out through Graph after switching `MAIL_TRANSPORT`, without the gate. Each upload is sent once, so a mock test run uses up the draft. |
| Send outcomes (stage 10, mapping for stage 12) | `SendResult` is success, retryable (optionally with `retry_after`), **unknown**, auth or permanent. Graph must map: connect error or connect/pool timeout before the request was sent, and 429/503 (with or without `Retry-After`) → retryable; read/write timeout after sending started, connection dropped mid-response, 500/502/504 (any 5xx) without a clear "not processed" → unknown; 401 / `invalid_grant` → auth; other 4xx → permanent. Unknown: the recipient is `failed` ("outcome unknown (...) — may or may not have been delivered; check Sent Items"), never retried, `send_log.outcome` left NULL (counts against the cap until it leaves the 24 h window), and it counts as a consecutive failure. Any exception from `transport.send` other than `MessageError` is unknown; exceptions while building the message stay retryable (nothing was sent). | Retrying after Microsoft may have accepted the message risks a double email, which can't be undone; reporting it lets Jake check Sent Items. Counting it against the cap stays under Microsoft's limit. Several unknowns in a row mean something is wrong, so they still stop the campaign. |
| Throttling (stage 10) | A retryable result with `Retry-After` is stored as an absolute "not before" time (`send_throttle`, one row), so it survives restarts; pacing waits for it, so no transport call for **any** recipient happens before it, and the progress page shows it as the next send time. The throttled recipient waits until then. Throttles don't count as consecutive failures or as one of the recipient's 3 attempts; 10 throttles in a row (no success between) stop the campaign; resuming resets the count. Plain retryable failures keep the per-recipient backoff (30 s, 2 min, 10 min). | `Retry-After` is the server asking the whole account to slow down, not a failure of one message: carrying on with other recipients would be ignored or make it worse, and failing recipients because of it would make Jake resend them by hand. The 10-in-a-row stop keeps a server that never stops throttling from keeping the send going forever. |
| Shutdown timing (stage 10, 12, 14) | Graph request timeout (stage 12, set it to about 10 s) < `SHUTDOWN_GRACE_SECONDS` (15 s, how long the worker waits for an in-flight send at shutdown) < the container stop grace period (`stop_grace_period: 30s` in `compose.yaml`). The Unraid template (stage 14) must do the same: Unraid's Docker manager uses `docker stop` with Docker's default 10 s, so the template adds `--stop-timeout=30` to Extra Parameters. | If Docker kills the container mid-send, that recipient is reported "interrupted" and has to be checked by hand. With this order an in-flight request always ends (sent, or timed out) and its outcome is saved before the process is killed. |
| Database connections (stage 10) | `Database.init` keeps one connection open for the app's lifetime (closed at shutdown) and every connection uses `PRAGMA synchronous=NORMAL` (WAL mode). The worker's database work runs in a thread. If writing an outcome fails it is retried (0.5 s, 2 s, 5 s), then kept in memory and written before anything else is sent; after 10 failed tries in all it is dropped (logged as an error), the recipient stays `sending` and the campaign is stopped (`stopped_error`) until a restart reports it as interrupted. A campaign never finishes while a recipient is `sending`. | With no connection open SQLite deletes and recreates the WAL on every short-lived connection, which was slow. `NORMAL` is safe in WAL mode (a power cut may lose the last commit, never corrupt the file). Threads keep the web pages responsive while a message is recorded. Losing a successful send's record would report it as interrupted. |
| Uploaded CSV retention (stage 10) | Deleted when its campaign finishes or is cancelled (also when a stopped campaign is cancelled). At startup, CSVs of drafts older than 7 days that never became a campaign are deleted, as are any left by a finished or cancelled campaign. Campaign tables are kept. | The CSV holds the customer list and changes every time; the send log is the record of what went out. |
